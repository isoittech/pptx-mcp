# ADR 0008: Visual Deckの追加ページだけをモデルから受け取る

## 状態

採用

## 背景

成功済みVisual Deckへページを追加する要求に対し、既存の`pptx_refine_visual_slide`は既存ページ番号の差し替えだけを許可していた。ページ数を増やすには、モデルが元の全ページと追加ページを再構築し、作成ツールへ完全な`VisualDeckSpec`を再送する必要があった。大きな構造化入力はBedrockで省略や空呼び出しを招きやすく、既存ページの意図しない改変にもつながる。

## 決定

- `pptx_insert_visual_slides`は追加する1ページ以上の`VisualSlideSpec`だけを受け取る。
- `jobId=latest`で同じ利用者・会話の最新成功Visual Deckを解決する。
- `afterSlideNumber`の省略時は末尾、`0`は先頭、正の値は既存の1始まりページ番号の直後へ挿入する。
- サーバーは元ジョブのタイトル、テーマ、デザイン、既存ページを保持し、ブランドVisual Deckでは元テンプレートと`templateLayoutId`も再利用する。
- 結合後の上限を50ページとし、通常はサーバー内で最大30秒完了を待つ。
- 第1段階では結合後の完成版を既存レンダラーで全ページ再生成し、Open XML検証と全ページプレビューを行う。

## 結果

モデルの構造化入力は追加ページ分だけとなり、資料全体の再送、既存ページの再考、作成ツールの空呼び出し反復を避けられる。ファイル生成時間は引き続きページ数に比例する。既存PPTXパーツを保持して新規ページだけを物理的に追加する差分編集は、全体レンダリング時間が実測上のボトルネックになった場合に別途検討する。
