# ADR 0024: 指定ページだけを生成・出力する

## 状態

採用

## 背景

本文1枚だけを差し替え用に作りたい場合でも、先頭ページを表紙とする検証とテンプレート合成が適用されていた。また、既存のVisual Deck修正は全ページを再生成するため、修正した1枚だけを受け取れなかった。

## 決定

- draft開始時に`firstSlideIsCover`を固定し、検証、HTML描画、テンプレート合成で同じ値を使う。省略時は従来どおり`true`、本文だけの資料は`false`とする。表紙を自動追加しない。
- `pptx_refine_visual_slide(outputOnlyRevisedSlide=true)`は、既存ページの修正契約を検証した後、その1枚だけをレンダラーへ渡す。元資料を置き換えず、別資料の系統を作る。元の修正巡数は引き継ぎ、上限回避には使えない。
- 別資料ではページ番号を1から数える。`source_slide_numbers`に元資料との対応を残し、Brand Profileのページ計画と監査記録を出力番号へ対応付ける。ノートと準備済みアセットの内容は引き継ぐ。
- 変更なしの抽出は`pptx_export_slides`で行う。現在の添付または同じ利用者・会話の有効な成功jobから、指定順に別PPTXを作る。生成モデルとVisual Deckレンダラーは通さず、Open XMLの部品を保持する。
- 除外ページへの内部リンク、custom show・sectionの参照、古い全体サマリーとサムネイルを除く。未対応の参照が残る場合は失敗させ、破損した成果物を返さない。
- 生成・抽出後は出力側の全ページをプレビューする。通常の全体資料への修正は、既存の既定動作を維持する。
- 準備済みvisual objectを持つ部分資料へのページ挿入は、元ページとの対応が失われるため拒否する。この場合は元資料へ追加してから対象ページを出力する。

## 結果

本文1枚の新規作成、修正1枚の生成、指定ページの抽出を分けて扱える。利用者が要求した出力枚数を守りつつ、元資料を保持できる。会話側のinstructions、Skill、tool manifestにも同じ選択基準を反映し、手作業の編集説明だけで終了させない。
