# ADR 0012: Visual Deck生成ループをサーバー側で停止する

## 状態

採用

## 背景

長い会話ではなく1回の資料作成中に、モデルがテンプレートや配色を完成後に見直し、`pptx_start_visual_deck`から全体生成を繰り返す事象が発生した。さらに追加バッチで必須だった`startSlideNumber`を省略してスキーマエラーを繰り返し、差分修正の「最大2巡」は指示文だけで強制されていなかった。結果として、成功済み成果物があるにもかかわらずLangGraphの再帰上限を消費した。

## 決定

- `startSlideNumber`を任意にし、省略時はドラフトの受理済み末尾から次番号を算出する。明示された誤番号は重複防止のため拒否する。
- テンプレート、テーマ、デザインは`pptx_start_visual_deck`で固定する。finish時の上書きは拒否する。
- テンプレート由来の色とフォントは未指定項目だけを補完し、startで明示した値を優先する。
- 同じ会話でVisual Deck生成が成功した後は、通常のstartを拒否し、ページ修正またはページ挿入へ誘導する。ユーザーが別資料を明示した場合だけ`userRequestedNewWorkflow=true`で新しいワークフローを許可する。
- 初回生成が失敗またはキャンセルされた場合の全体再試行は1回だけ許可する。2回失敗後は停止してエラーを報告する。
- Visual Deckジョブへ`VisualRootJobId`、`ParentJobId`、修正巡、同巡の修正済みページを保存する。修正は最新成功ジョブから1ページずつだけ受理し、古いジョブからの分岐、並行変更、3巡目を拒否する。
- ページ挿入後は修正巡を0へ戻し、追加後の完成版を改めて最大2巡確認できるようにする。

## 結果

再帰上限を引き上げなくても、全体再作成と視覚修正の停止条件をMCPが決定的に適用できる。複数の問題ページは同じ巡の中で順番に修正でき、同じページを再修正した時点で次巡へ進む。

一方、MCPはユーザー発話そのものを検証できないため、`userRequestedNewWorkflow=true`が本当に明示依頼に基づくかはクライアントエージェントの責務である。また、ページ単位の差分入力でも現行レンダラーは完成版PPTXと全ページプレビューを再生成する。これはモデル入力とジョブ制御の差分化であり、OOXMLファイルの物理的な部分書き換えではない。
