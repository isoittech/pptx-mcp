# ADR 0011: 楽譜を意味入力から編集可能なPowerPoint要素へ変換する

- 状態: 採用

## 文脈

ウクレレ教材では、五線譜とTABを対応させ、左手の指を色分けした図が必要になる。PNGやSVGを貼る方式ではPowerPoint上で線、音符、フレット番号を個別編集できない。一方、モデルへ任意座標や任意JavaScriptを公開すると、Visual Deckの宣言型実行境界を崩す。

## 決定

- Visual Deckへ`MusicScore`レイアウトと、音高、音価、小節、弦、フレット、指番号からなる制限付きモデルを追加する。
- 五線、符幹、小節線、TAB線、フレット番号、指色マーカーを固定PptxGenJSレンダラーでPowerPointネイティブ要素へ変換する。
- ト音記号、拍子数字、符頭、旗、付点、休符、臨時記号はSMuFL 1.4準拠のBravura 1.392からOpenType輪郭を読み、PptxGenJSの`custGeom`へ直接変換する。PPTXには画像やフォントを埋め込まず、字形ごとに編集可能なPowerPointカスタム図形を生成する。
- Bravuraの原本OTFとSIL Open Font License原文を`visual-renderer/assets/bravura/`へ同梱し、バージョンを固定する。輪郭抽出にはMITライセンスの`opentype.js`を固定バージョンで使う。
- 初期対応はト音記号、High-G/Low-Gウクレレ、1〜8小節、合計64イベント、全音符から16分音符までとする。
- 弦番号は1=A、2=E、3=C、4=Gとし、入力音高が調弦とフレットから得られる音高に一致しない場合は拒否する。
- 楽譜入力に任意座標、画像、URL、フォントファイル、JavaScriptを追加しない。

## 理由

- 成果物内の各要素をPowerPointで移動、色変更、削除できる。
- 音楽データを座標から分離し、同じ入力を白紙資料とブランドVisual Deckの両方で安全に再生成できる。
- 音高とTABの不整合を生成前に検出し、教材としての誤記を減らせる。
- Bravuraは楽譜浄書を目的に設計されたSMuFL参照フォントであり、手描き近似より記号品質が高い。字形輪郭を図形化するため、閲覧側へのフォント導入やフォント埋め込み可否にも依存しない。

## 結果

PowerPointには専用の楽譜意味モデルがないため、移調、連桁の再計算、改行、音価変更に伴う自動組版は行わない。複雑な連桁、連符、装飾音、スラー、複数声部、反復記号は初期範囲外とし、必要になった機能を意味フィールドと固定描画として段階的に追加する。

Bravuraの輪郭は生成物へ複製されるため、配布元のSIL Open Font Licenseを資産と一緒に保持する。生成された通常文書にOFLを継承させる必要はないが、フォント原本や改変フォントを再配布する場合はOFLの条件に従う。
