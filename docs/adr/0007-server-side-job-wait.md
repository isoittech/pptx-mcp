# ADR 0007: 非同期ジョブのサーバー内待機

## 状態

採用

## 背景

PowerPoint生成はバックグラウンドジョブとして実行される。従来はモデルが`pptx_get_job`を短い間隔で再実行しており、Web調査など先行処理が長い会話では、成果物完成前にLibreChat／LangGraphの再帰上限へ達することがあった。

## 決定

- `pptx_wait_for_job`を読み取り専用・冪等なMCPツールとして追加する。
- 同ツールはジョブ所有者と会話境界を検証したうえで、既定45秒、最大50秒だけMCPサーバー内で待つ。
- 待機中に`jobId=latest`が別ジョブへ切り替わらないよう、開始時に具体的なジョブIDへ固定する。
- 終端状態になれば解析結果と署名付き成果物URLを返す。
- 時間内に終わらなければ最新状態を返し、モデルは同じジョブIDでもう一度だけ待機できる。
- `pptx_get_job`は即時状態確認と障害復旧用として維持する。
- 単一ページ視覚修正が直接`Succeeded`を返した場合は、どちらの状態確認ツールも追加で呼ばない。

## 結果

- 長いジョブでも1回のMCPツールラウンドで完了を受け取れる可能性が高くなる。
- LibreChatの再帰上限とモデルAPI呼び出し回数を節約できる。
- MCPクライアントのタイムアウトより余裕を持たせるため、1回の待機上限は50秒とする。
- 50秒を超えるジョブでは複数回の待機が必要だが、短間隔ポーリングより呼び出し回数を大幅に抑えられる。
