# ADR 0010: 文字量を縮小ではなく構造化で収容する

- 状態: 採用

## 文脈

業務報告やコンサルティング資料では、1ページに500〜900文字程度を載せながら、見出しだけで概要を追える読みやすさが必要になる。従来のVisual Deckは大きいカードと余白を中心としたプレゼン向け構図で、`density=detailed`もフォント倍率を0.93にするだけだった。このため情報量を増やすほど、本文枠への詰め込みと文字縮小に寄りやすかった。

複数の参考資料を比較すると、読みやすさを支える主な要因は小さい文字ではなく、外周とブロック間の余白、見出し付きの小領域、明確な読む順序、薄い罫線、限定した意味色、繰り返し構造だった。

## 決定

- Visual Deckの意味レイアウトを17種類から19種類へ拡張する。
- `StructuredBrief`を追加する。
  - 2〜3個の`sections`を横方向の読む順序で配置する。
  - 各セクションは見出し、本文、任意の実箇条書き、短い強調ラベル、意味色を持つ。
  - 1ページのセクション文字数は合計900文字までとし、超える場合はページ分割を求める。
  - 3セクション・600文字未満は主論点を上段へ置くモザイク、600文字以上は3列とし、短い内容ほど本文と箇条書きを拡大する。
- `Scorecard`を追加する。
  - 2〜4個の選択肢と2〜6行の評価軸を扱う。
  - 各行は選択肢と同数の評価セルを必須にする。
  - 評価、短い根拠、意味色をPowerPointネイティブ表として描画する。
- `density=detailed`を独立したデザイントークン群にする。
  - 外周余白と見出し領域を縮め、コンテンツ領域を広げる。
  - 内部間隔を詰め、角丸と影を除き、薄い罫線を使う。
  - 本文を一律に小さくせず、新規の高密度レイアウトでは9pt以上の固定サイズを使う。
- 視覚リフレクションへ次の評価軸を追加する。
  - 見出しだけで話が追える。
  - 読む順序が一意である。
  - 1ブロックに主要論点が1つである。
  - 強調色は概ねページの15%以内である。
  - 本文が9pt未満に見えない。
- 500文字以上のページで`detailed`を使わない場合、見出し重複、全セクションの過剰強調を非停止の`design_warnings`として返す。

## 理由

- 文章量を保ったまま、利用者が見出し、要点、根拠の順に読める。
- 生成モデルは意味構造と強調対象を選び、固定レンダラーは安全な座標、文字サイズ、編集可能性を保証できる。
- 会社固有テンプレートやプロンプトをOSSへ埋め込まず、任意の導入環境で再利用できる。
- 表を画像化せず、PowerPoint上で評価と根拠を直接編集できる。

## 不採用案

- `detailed`で全フォントを一律に小さくする: 情報構造を改善せず、投影・印刷時の可読性を落とすため採用しない。
- 任意座標をモデルへ公開する: 表現力は上がるが、入力サイズ、重なり、監査、再現性の境界が広がるため採用しない。
- 参考資料の企業デザインを固定テンプレートとして同梱する: OSSへ固有ブランドを混入させるため採用しない。

## 結果

`StructuredBrief`と`Scorecard`で扱えない二次元構造として、フェーズ×担当レーン、主張×根拠×示唆、注釈付きフローが残る。これらは実利用とE2Eで必要性を確認した後、同じ意味ベースの契約として追加する。
