# ADR 0002: 白紙生成を宣言型PptxGenJSとエージェント駆動視覚評価で実装する

- 状態: 採用

## 文脈

テンプレート編集だけでは、白紙から華やかな資料を自律生成する表現力が不足します。一方、参考記事のようにモデルが生成した任意JavaScriptを実行すると、任意コード実行、依存追加、ネットワークアクセス、再現性、監査の範囲が大きくなります。さらに、生成後の画像をClaudeが実際に見なければ、文字切れや重なりを会話内で自律修正できません。

## 決定

- 白紙生成専用の `IVisualPresentationEngine` を既存の編集用 `IPresentationEngine` と分離する。
- PptxGenJS 4.0.1を固定し、固定スクリプトが制限付き `VisualDeckSpec` だけを解釈する。
- AIには意味ベースの11レイアウト、5テーマ、制限付きコンテンツ、編集可能グラフデータだけを公開する。
- AIから任意JavaScript、任意座標、ファイルパス、URLを受け取らない。
- 生成・編集後のPNGを `pptx_get_preview_images` で最大4枚ずつMCP画像ブロックとしてClaudeへ返す。
- Claudeが全ページを評価し、問題時は宣言型仕様を修正して最大2回まで再生成する。
- BedrockでMCP画像artifactをモデルへ渡すため、LibreChat側に再現可能でフェイルクローズな依存パッチを適用する。

## 理由

- テキストと図形だけのテンプレート流し込みより、構図、カード、KPI、工程、タイムライン、グラフの表現力が高い。
- グラフは画像ではなく編集可能なPowerPoint要素と埋め込みワークブックになる。
- 任意コード実行を許可せず、既存の非root・read-only・外部ネットワーク遮断を維持できる。
- MCP画像ブロックは標準機能であり、PPTX本体をモデルコンテキストへ載せずに必要なページだけ評価できる。
- MCPサーバーへ別のモデル認証情報を持たせず、LibreChatの会話文脈とClaudeをそのまま利用できる。

## 結果

自由な任意配置や生成画像中心のデザインより表現範囲は限定されます。必要な構図は固定レイアウトとして追加し、入力上限とレンダリングテストを同時に更新します。視覚評価の実行はモデルのツール追従に依存するため、MCPサーバー指示、ツール説明、E2Eで確認します。依存更新時はPptxGenJS出力とLibreChatのBedrock画像経路を再検証します。
