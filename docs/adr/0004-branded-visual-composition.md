# ADR 0004: Visual Deckを企業テンプレートの白紙レイアウトへ合成する

- 状態: 採用

## 文脈

企業テンプレートのプレースホルダーだけを使う生成は、マスター、ロゴ、フッターを忠実に維持できますが、カード、KPI、工程、マトリクス、ダッシュボード等の表現力がレイアウト定義に制約されます。一方、テーマ色だけをVisual Deckへ転記する方法では、実際のマスター、ロゴ、フッターを保持できません。

## 決定

- 段階ドラフトで完成した `VisualDeckSpec` とアップロード済み企業テンプレートを `pptx_finish_branded_visual_deck` で受け取る。
- テンプレートのテーマ色と日本語フォントを自動抽出し、Visual Deckで未指定のテーマ項目だけを補完する。startで明示した色とフォントは維持する。
- 固定PptxGenJSレンダラーで編集可能な図形、ネイティブグラフ、埋め込みワークブックを生成する。
- Open XMLで企業テンプレートを成果物の基底にし、既存スライドを生成スライドへ置き換える。
- 生成スライドは企業テンプレートのプレースホルダー0個のレイアウトへ再接続する。自動選択ではフッター付き白紙レイアウトを優先し、写真背景を避ける。
- 合成時だけVisual Deck独自の下部フッターを抑制し、企業フッターと重複させない。
- テンプレートと生成デッキの縦横比が一致しない場合、または白紙レイアウトがない場合は明示的に失敗させる。
- `pptx_refine_visual_deck` と1ページ入力の `pptx_refine_visual_slide` は元ジョブのテンプレートとレイアウトを再利用し、変更ページだけを差し替える。
- 固定レンダラーの出力直後に、レンダラーが生成したプレゼンテーションルートと折れ線・棒グラフのOOXMLを正規化する。PptxGenJS 4.0.1が出力する`p:notesMasterIdLst`の不正な順序、折れ線グラフの不足した`c:grouping`、無効な`c:invertIfNegative`、`c:marker`の不正な順序、2Dグラフの余分な3本目の`c:axId`だけを対象とする。
- Visual Deck単体はOpenXmlValidatorでエラー0件を必須とし、企業テンプレートへの合成後もテンプレート由来の既存エラーを増やしていないことを検証する。検証に失敗した成果物は配布しない。
- PptxGenJSが自動生成する空のノートスライドは企業テンプレートへ取り込まない。`VisualSlideSpec.speakerNotes`がある非空ノートは保持し、テンプレート側のノートマスターがあれば再利用し、なければ生成側から1件だけ取り込む。スライド単位の`AddPart`で共有ノートマスターがページごとに複製されることを防ぐ。発表者ノートの契約はADR 0018に記録する。

## 理由

- ブランド要素を画像として模倣せず、正本であるマスターとレイアウトを保持できる。
- Opusが選んだ意味レイアウトと構図を、既存テンプレートのプレースホルダー数に制約されず表現できる。
- 図形とグラフの編集可能性、任意コードを実行しないセキュリティ境界、決定的な再生成を維持できる。
- 厳密なテンプレート流し込みと華やかなブランド資料を別ツールに分け、モデルが目的に合う経路を選べる。
- LibreOfficeのプレビュー成功だけでは、デスクトップ版PowerPointの修復警告を検出できない。Open XML SDKによるスキーマ検証を配布前ゲートにすることで、PowerPoint固有の厳密な要素順と要素制約を確認できる。
- OpenXmlValidatorは、プレゼンテーションへ未登録のノートマスターが各ノートスライドから参照されるような部品間の意味的不整合をすべて検出するわけではない。合成処理は不要な生成ノートを明示的に除去し、パッケージ部品数も回帰テストする。

## 結果

白紙レイアウト上で企業マスターの固定要素とVisual Deckの描画領域が重なるテンプレートは、レイアウト選択またはVisual Deck側の安全領域調整が必要です。すべてのブランドレイアウトに自動適応する任意配置ではないため、提供テンプレートとLibreOfficeプレビューを使ったE2Eを継続します。

PptxGenJSの更新時は正規化処理が引き続き必要かを回帰テストで判断します。依存パッケージを直接パッチせず、正規化対象を固定レンダラーが生成したプレゼンテーションルートとグラフ部品に限定します。
