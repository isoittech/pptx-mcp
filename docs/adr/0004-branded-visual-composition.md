# ADR 0004: Visual Deckを企業テンプレートの白紙レイアウトへ合成する

- 状態: 採用

## 文脈

企業テンプレートのプレースホルダーだけを使う生成は、マスター、ロゴ、フッターを忠実に維持できますが、カード、KPI、工程、マトリクス、ダッシュボード等の表現力がレイアウト定義に制約されます。一方、テーマ色だけをVisual Deckへ転記する方法では、実際のマスター、ロゴ、フッターを保持できません。

## 決定

- `pptx_create_branded_visual_deck` を追加し、完全な `VisualDeckSpec` とアップロード済み企業テンプレートを受け取る。
- テンプレートのテーマ色と日本語フォントを自動抽出し、Visual Deckのテーマへ上書きする。モデルによる値の転記は不要とする。
- 固定PptxGenJSレンダラーで編集可能な図形、ネイティブグラフ、埋め込みワークブックを生成する。
- Open XMLで企業テンプレートを成果物の基底にし、既存スライドを生成スライドへ置き換える。
- 生成スライドは企業テンプレートのプレースホルダー0個のレイアウトへ再接続する。自動選択ではフッター付き白紙レイアウトを優先し、写真背景を避ける。
- 合成時だけVisual Deck独自の下部フッターを抑制し、企業フッターと重複させない。
- テンプレートと生成デッキの縦横比が一致しない場合、または白紙レイアウトがない場合は明示的に失敗させる。
- `pptx_refine_visual_deck` と1ページ入力の `pptx_refine_visual_slide` は元ジョブのテンプレートとレイアウトを再利用し、変更ページだけを差し替える。

## 理由

- ブランド要素を画像として模倣せず、正本であるマスターとレイアウトを保持できる。
- Opusが選んだ意味レイアウトと構図を、既存テンプレートのプレースホルダー数に制約されず表現できる。
- 図形とグラフの編集可能性、任意コードを実行しないセキュリティ境界、決定的な再生成を維持できる。
- 厳密なテンプレート流し込みと華やかなブランド資料を別ツールに分け、モデルが目的に合う経路を選べる。

## 結果

白紙レイアウト上で企業マスターの固定要素とVisual Deckの描画領域が重なるテンプレートは、レイアウト選択またはVisual Deck側の安全領域調整が必要です。すべてのブランドレイアウトに自動適応する任意配置ではないため、提供テンプレートとLibreOfficeプレビューを使ったE2Eを継続します。
