# Visual Component Catalog

> `visual-v7-author-html`では、この一覧は内容構造を考えるための部品語彙であり固定レイアウトの金型ではない。会話モデルが同じ情報構造を必要に応じて組み替え、完成したHTML/CSSを設計する。serverがここに記載された固定構図へ戻すことはしない。保存済み`visual-v6-dom`の互換生成では従来のrenderer選択基準として使う。

## 目的

Visual Deckのレイアウトを完成形の「金型」ではなく、内容に応じて組み替える「部品セット」として管理する。モデルは座標、HTML、CSS、SVGを生成せず、意味データだけを`VisualDeckSpec`へ渡す。サーバーが承認済みDOM/CSSまたはPowerPointネイティブ要素へ変換する。

共通原則は次のとおり。

- 1枚1メッセージを明確にし、結論、根拠、示唆、行動のどこを担うページか決める。
- 本文は原則14pt以上とし、収まらない場合は縮小せず、文章整理またはページ分割を行う。出典・URL・発行日は12ptまで許容する。
- 文字・図形に影を付けず、塗り、線、余白、整列で階層を作る。
- Chip UIは、枠内の説明を端的に名付けるラベルとして使う。装飾目的で増やさない。
- アイコン、人物、吹き出し、図、数値、表は、理解を助ける場合だけ選ぶ。特定の内容に固定しない。
- 原資料にない発言、関係、因果を追加しない。仮説を使う場合は仮説と明示する。
- 暗い背景ではフッターを白系へ切り替える。LibreOffice画像とPowerPoint表示が異なる場合は、PowerPoint側を最終判断とする。

## 部品

### CoverageMap

複数の行について、どの時点・工程・領域に適用されるかを対応付ける。法令一覧に限定せず、責任分担、機能提供範囲、施策対象、品質管理、運用範囲にも使える。

- 入力: 2〜6列、最大8行、1始まりの列span、任意のcallout、任意のfooter chip
- 適する問い: 「何が、どこまで、いつ関係するか」
- 避ける用途: 単純な箇条書き、時間軸のない比較

### TransformationEvidence

入力の注目箇所、変換後の結果、結果を裏付ける表を一続きで示す。個人情報マスキングに限定せず、分類、正規化、抽出、要約、照合にも使える。

- 入力: 安全文字segmentと任意tag、変換後文字列、編集可能な検証表
- 適する問い: 「何をどう変え、何で正しさを確認したか」
- 禁止: raw HTML、モデル生成script、未検証画像やパス

### ArtifactShowcase

確認済みの画像assetを、成果物や提供物のまとまりとして見せる。画像は飾りではなく、実在する成果物の証拠として使う。

- 入力: 1〜3グループ、各1〜4件の会話scope付きasset ID
- 適する問い: 「具体的に何を納品・提供するか」
- 禁止: 空プレースホルダー、外部URL、権利未確認素材

### GanttSchedule

カテゴリ、タスク、時間セル、期間spanを編集可能な工程表として示す。

- 入力: 4〜12時間セル、2〜8タスク、任意marker・legend・工数ラベル
- 適する問い: 「誰が何をいつ進めるか」
- 長い場合: 週次を月次へ集約するか、期間ごとにページ分割する

## 汎用の補助部品

- Chip: 取り組み名、短期試作、長期試作、状態、担当方式などの短い名前
- Callout: 実在する行・bar・task・evidence itemへの短い補足。吹き出し形状はPowerPointネイティブ図形を優先する
- Lucide icon: 承認済み意味IDからサーバーが解決する。人物、組織、工程、表、日程、成果物、研修等を含む
- Image asset: 人物に限らず、イラスト、写真、画面、文書、図版を同じ検証済みasset契約で扱う

## レンダリングの役割分担

- 標準本文ページ: サーバー管理DOMを`dom-to-pptx`で変換する。
- NativeDiagramのtree/flow: サーバー管理DOMで、編集可能なノードと接続線を描画する。独立ノード間には明確な空白を保つ。
- native chart、dashboard、NativeDiagramのcycle/concentric/network、musicScore: PptxGenJS/Open XMLのネイティブ要素を維持する。
- 混在deck: deck全体を旧方式へ戻さず、ページ単位でDOMとネイティブ描画を合成する。
- 既定テンプレート: 導入環境がcover/bodyの見本スライド番号を設定した場合、1枚目はcover、2枚目以降はbodyのレイアウトを使う。
- 既定テンプレートの本文見出し規則を有効にした場合: タイトルと主張を別オブジェクトにし、タイトル30pt、主張16pt実箇条書き、両方Accent 2とする。
- ユーザー指定テンプレート: 導入環境の既定cover/body設定を適用せず、ユーザーが選んだlayoutを優先する。

## 品質確認

LibreOfficeで全ページを画像化し、欠け、重なり、読む順序、情報量、出典、メッセージの明確さを確認する。ただし、グラデーション、文字詰め、行間などの差異はPowerPointでも確認し、LibreOffice固有の差を修正理由にしない。
